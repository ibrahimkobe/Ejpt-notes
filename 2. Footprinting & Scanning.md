### Networking Fundamentals


- **Network protocols** are the standardized sets of rules that govern how data is exchanged between devices over a network. Without them, a computer from one manufacturer wouldn't be able to "speak" to a router or server from another.

### Network Layer

- The Network Layer (Layer 3) of the OSI model is responsible for logical addressing, routing, and forwarding data packets between devices across different networks.
	
- Its primary goal is to determine the optimal path for data to travel from the source to the destination, even if the devices are on separate networks.
	
- The network layer abstracts the underlying physical network, allowing for the creation of a cohesive internetwork.

#### Network Layer Protocols

**Several key protocols operate at the network layer (Layer 3) of the OSI model. Here are some prominent network layer protocols:**
- **Internet Protocol (IP):**
	IPv4 (Internet Protocol version 4): The most widely used version of IP, employing 32-bit addresses and providing the foundation for communication on the Internet.
	IPv6 (Internet Protocol version 6): Developed to address the limitations of IPv4, it uses 128-bit addresses and offers an exponentially larger address space.

- **Internet Control Message Protocol (ICMP):**
	Used for error reporting and diagnostics. ICMP messages include ping (echo request and echo reply), traceroute, and various error messages

### Transport Layer

- The Transport Layer is the fourth layer of the OSI (Open Systems Interconnection) model, and it plays a crucial role in facilitating communication between two devices across a network.
	
- This layer ensures reliable, end-to-end communication, handling tasks such as error detection, flow control, and segmentation of data into smaller units.
	
- The Transport Layer, is responsible for providing end-to-end communication and ensuring the reliable and ordered delivery of data between two devices on a network.

#### Transport Layer Protocols
- **TCP (Transmission Control Protocol):** Connection-oriented protocol providing reliable and ordered delivery of data.
	
- **UDP (User Datagram Protocol):** Connectionless protocol that is faster but provides no guarantees regarding the order or reliability of data delivery.

#### TCP Port Range
**Well-Known Ports (0-1023): Port numbers from 0 to 1023 are reserved for well-known services and protocols. These are standardized by the Internet Assigned Numbers Authority (IANA). 
Examples include:
+ 80: HTTP (Hypertext Transfer Protocol)
+ 443: HTTPS (HTTP Secure)
+ 21: FTP (File Transfer Protocol)
+ 22: SSH (Secure Shell)
+ 25: SMTP (Simple Mail Transfer Protocol)
+ 110: POP3 (Post Office Protocol version 3)

### Network Mapping

- Network mapping in the context of penetration testing (pentesting) refers to the process of discovering and identifying devices, hosts, and network infrastructure elements within a target network.
	
- Pentesters use network mapping as a crucial initial step to gather information about the network's layout, understand its architecture, and identify potential entry points for further exploitation.

🔹**Objectives of network mapping**

1. *Discovery of Live Hosts:* Identifying active devices and hosts on the network. This involves determining which IP addresses are currently in use.
	
2. *Identification of Open Ports and Services:* Determining which ports are open on the discovered hosts and identifying the services running on those ports. This information helps pentesters understand the attack
surface and potential vulnerabilities.
	
3. *Network Topology Mapping:* Creating a map or diagram of the network topology, including routers, switches, firewalls, and other network infrastructure elements. Understanding the layout of the network assists
in planning further penetration testing activities.
	
4. *Operating System Fingerprinting:* Determining the operating systems running on discovered hosts. Knowing the operating system helps pentesters tailor their attack strategies to target vulnerabilities specific to that OS.
	
5. *Service Version Detection:* Identifying specific versions of services running on open ports. This information is crucial for pinpointing vulnerabilities associated with particular service versions.
	
6. *Identifying Filtering and Security Measures:* Discovering firewalls, intrusion prevention systems, and other security measures in place. This helps pentesters understand the network's defenses and plan their approach accordingly.

🔹**Nmap (Network Mapper)**
>Nmap, or Network Mapper, is an open-source network scanning tool used for discovering hosts and services on a computer network, finding open ports, and identifying potential vulnerabilities.

	i. Host Discovery  ii. Port Scanning    iii. Service Version Detection  V. Operating System Fingerprinting

### Host Discovery Techniques

>**host discovery is a crucial phase to identify live hosts on a network before further exploration and vulnerability assessment.**
##### 🔹*Techniques* 
1. **Ping sweeps (ICMP Echo Requests):** Sending ICMP Echo Requests (ping) to a range of IP addresses to identify live hosts.
2. **ARP Scanning:** Using Address Resolution Protocol (ARP) requests to identify hosts on a local network. ARP scanning is effective in discovering hosts within the same *broadcast domain.*
3. **TCP SYN Ping (Half Open Scan):** Sending TCP SYN packets to a specific port (often port 80) to check if a host is alive. If the host is alive, it responds with a TCP SYN-ACK. This technique is stealthier than ICMP ping.
4. **UDP Ping:** Sending UDP packets to a specific port to check if a host is alive. This can be effective for hosts that do not respond to ICMP or TCP probes.
5. **TCP ACK Ping:** Sending TCP ACK packets to a specific port to check if a host is alive. This technique expects no response, but if a TCP RST (reset) is received, it indicates that the host is alive.
6. **SYN-ACK Ping:** (Sends SYN-ACK packets): Sending TCP SYN-ACK packets to a specific port to check if a host is alive. If a TCP RST is received, it indicates that the host is alive.
##### 🔹*Pros & Cons:*

**ICMP Ping:**
- Pros: ICMP ping is a widely supported and quick method for identifying live hosts.
- Cons: Some hosts or firewalls may be configured to block ICMP traffic, limiting its effectiveness. ICMP ping can also be easily detected.
**TCP SYN Ping:**
- Pros: TCP SYN ping is stealthier than ICMP and may bypass firewalls that allow outbound connections.
- Cons: Some hosts may not respond to TCP SYN requests, and the results can be affected by firewalls and security devices.

### Ping Sweeps

>network scanning technique used to discover live hosts (computers, servers, or other devices) within a specific IP address range on a network. 
>*Its a Transport layer protocol*

🔹**How it works?** The basic idea is to send a series of ICMP Echo Request (ping) messages to a range of IP addresses and observe the responses to determine which addresses are active or reachable.
🔹**Command:** `ping <www.site.test>`
🔹**To specify the amount of ICMP packets to send:** `ping -c <num of packets> <IP address>`

🔹**To ping a broadcast:** `ping -b -c <num of packets> <Network ID>`
🔹**A Better tool:** *fping* , its an enhanced version from *ping* 
##### Fping
> similar to the standard `ping` utility, but it is specifically designed to handle multiple hosts simultaneously.

While a standard `ping` sends an ICMP Echo Request to a single target and waits for a response before moving on (sequential), `fping` sends out requests to multiple targets in a round-robin fashion (parallel). This makes it significantly faster when you need to sweep an entire network or check a large list of IP addresses.
**Why use fping over standard ping?**

For network mapping, host discovery during an engagement, or quick subnet troubleshooting, `fping` is highly efficient.

- **Speed:** It doesn't wait for a timeout on a dead host before pinging the next one.
    
- **Scriptability:** Its output is highly parsable, making it easy to feed into bash scripts or other tools.
    
- **Flexibility:** You can pass it a CIDR notation subnet, an IP range, or a text file containing hundreds of targets.

🔹**Command:** `fping -a -g <NID/24 for example>`
- `-a` : show targets that are alive.
- `-g` : generate a target list, only if you are using a subnet that you want to test. 
🔹**A better way:** `fping -a -g <10.10.23.0/24> 2>/dev/null` 
- `2>/de/null` Now you will have a clean list with only the online hosts (it removes the errors).

### Port Scanning With Nmap

🔹**Normally, Nmap first checks:**
- ICMP ping
- TCP/UDP probes (like `-PS`, `-PA`)

If no response → it assumes the host is **down** and stops.

👉 But with `-Pn`:

- Nmap **does NOT care**
- It goes straight to **port scanning**
Example: `nmap -Pn 192.168.1.10`
Even if the target:
- Blocks ping
- Drops SYN packets

➡️ Nmap will still try to scan ports.

- `nmap -Pn -p- 10.4.24.205` this tells nmap to scan all the 65k ports.
- `nmap -sU 10.4.24.205` this is how to scan UDP ports

### Firewall Detection & IDS Evasion

- How to detect the presence of a firewall: `nmap -sA <IP_address>` ==Map firewall rules, Determine if ports are filtered or unfiltered==
>Example: `nmap -Pn -sA -p445,3389 10.4.27.83`  **NOTE:** we know that ports: 445,3389 are open but we specified them to know if they're filtered or not.
##### IDS Evasion
- `nmap -f`: Fragment packets (IP packet fragmentation)
>Example: `nmap -Pn -sS -sV -F -f` , -F: means fast sacn (only scans first 100 ports) , -f: means Fragment packets (IP packet fragmentation)

- `nmap -f -mtu <number>` manual packet fragmentation control.
>Example: `nmap -sS -sV -p80,445,3389 -f --mtu 32 10.4.27.83` , Forces each fragment to be **32 bytes**

- `nmap --data-length 200 -D <Gateway_IP_Address, Another_IP> <Target_IP>`: --data-length 200:  Adds **200 bytes of random data** to each probe packet **Why?**
1. Makes packets look less like typical Nmap scans
2. Can help evade **signature-based IDS/IPS**
3. increases packet size → less “fingerprintable”
👉 Makes it harder to identify the real scanner
>Example: `nmap -Pn -sS -sV -p445,3389 -f --data-length 200 -D 10.10.23.1,10.10.23.2 10.4.27.83`: 
>- `-Pn` → Skip host discovery (assume target is up)
>- `-sS` → SYN (stealth) scan
>- `-sV` → Service/version detection
>- `-p445,3389` → Target:
    - **445** → SMB (Windows file sharing)
    - **3389** → RDP (Remote Desktop)
>- `-f` → Fragment packets
>- `--data-length 200` → Add 200 bytes of random data
>- `-D 10.10.23.1,10.10.23.2` → Use decoy IPs
>- `10.4.27.83` → Target IP

- ==To change the source port to make it less suspicious== `nmap -Pn -sS -sV -p445,3389 -f --data-length 200 -g 53 -D 10.10.23.1,10.10.23.2 10.4.27.83` 
>- `-Pn` → skip host discovery (assume target is up)
>- `-sS` → SYN (half-open) scan
>- `-sV` → service/version detection
>- `-p445,3389` → target:
    - **445 (SMB)** → Windows file sharing
    - **3389 (RDP)** → Remote Desktop
>- `-f` → fragment packets
>- `--data-length 200` → pad packets with random 200 bytes
>- `-g 53` → **set source port to 53 (DNS)**
>- `-D 10.10.23.1,10.10.23.2` → use decoy IPs

### Optimizing Nmap Scans

>**Note:** Why do we need to slow down our scans sometimes? == when we are dealing with IDS , slowing down our scans will reduce the amount of packets being sent, it will look less suspicious , Also If we're dealing with an old IDS it might lead to an unintended denial of service, or you might cause the old switches and routers crash.

|Option|Nickname|Meaning|
|---|---|---|
|`-T0`|**Paranoid**|Extremely slow, avoids detection|
|`-T1`|**Sneaky**|Very slow, low chance of detection|
|`-T2`|**Polite**|Slows down to reduce network load|
|`-T3`|**Normal**|Default speed (balanced)|
|`-T4`|**Aggressive**|Fast, commonly used in labs|
|`-T5`|**Insane**|Very fast, noisy and unreliable|

### Nmap Output Formats

- `nmap -oN <File_Name.txt>`:Output results in “Normal” (human-readable) format to a file
>Example `nmap -Pn -sS -F -T4 10.4.19.132 -oN nmap_normal.txt`

- `nmap -oX <File_name.xml>`: Save scan results in XML format
>Example `nmap -Pn -sS -F -T4 10.4.19.132 -oX nmap_xml.xml`

- `nmap -oG <file_name.txt>`: Save output in grepable format (easy to filter with tools like `grep`, `awk`, etc.)
>Example `nmap -Pn -sS -F -T4 10.4.19.132 -oN nmap_grep.txt`
